title: "配置下限估算"
description: "按工作负载给一个 vCPU 和内存下限。这是经验假设，不是压测，也不读取实时价格。"
---

## 公式和单位

只输出 **vCPU 个数** 和 **内存 MB**。月访问量的单位是次/月，API 峰值的单位是次/秒。留空表示「不知道」，不是 0。

| 工作负载 | 起步 | 上调（仍是假设） |
|---|---|---|
| 静态站 | 1 vCPU / 1024 MB | 月访问量 > 100000 时，内存改为 2048 MB |
| CMS（一个站点，带数据库） | 1 vCPU / 2048 MB | 月访问量 > 50000 时，改为 2 vCPU / 4096 MB |
| 小型 JSON API | 2 vCPU / 2048 MB | 峰值 > 20 次/秒时内存改为 4096 MB；> 100 次/秒时停在单机 4 vCPU / 8192 MB |

API 不使用月访问量。超过 10000000 次/月，或超过 1000 次/秒，这张表不给配置，也不估计多台机器。

未启用脚本时，用上面的表自己算。启用脚本后，提交表单会标出下限，并链到比价页里内存和 vCPU **都不低于**该下限的套餐。内存或 vCPU 未知的套餐会被排除，因为未知不等于达标。
